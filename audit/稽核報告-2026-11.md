## 二、中風險

### M1｜開發筆記、本機路徑、私人內容公開在 repo

- **位置**：`PROGRESS.md`、`PROJECT_STATUS.md`（repo 根目錄）
- **問題**：這兩份是給自己（或 AI 助手）看的開發筆記，但跟著公開 repo 一起放在網路上。內容包含：
  - 電腦上的完整資料夾路徑，路徑裡有電腦使用者名稱
  - 私人相處細節、暱稱、問答題目的正確答案
  - 所用貼圖的來源編號
- **為什麼重要**：
  - 比喻：像把寫給自己的便利貼貼在家門口。單看沒什麼，但跟其他公開資訊拼起來，就能拼湊出你是誰、跟誰在一起。
  - 遊戲本身就需要題目與照片，這部分無法避免公開；但「開發筆記」對網站運作完全沒用，公開它只有風險。
- **建議怎麼修**：
  1. 把這兩份檔案移出版控（從 repo 刪除，本機保留），並加進 `.gitignore`
  2. 若想保留進度紀錄，改放私人筆記（Notion、私人 repo）
  3. 之後寫筆記時，路徑一律寫相對路徑（例如 `src/App.jsx`），不寫完整路徑
- **怎麼驗證**：在 GitHub 網頁版 repo 首頁看不到這兩份檔案；`git ls-files | grep -E "PROGRESS|PROJECT_STATUS"` 沒有輸出。
- **備註**：刪除後舊版仍留在 git 歷史，是否處理由你決定（與照片的做法一致即可）。

### M2｜Google 字型被建置工具丟掉，正式網站沒有載入

- **位置**：`src/index.css` 第 1～4 行
- **問題**：CSS 規定「`@import` 外部檔案」必須寫在檔案最上面。目前第 1 行先 `@import "tailwindcss"`，Tailwind 展開後產生大量規則，Google 字型的 `@import` 就變成「不在最上面」。建置時出現警告 `@import rules must precede all rules`，**最終輸出的 CSS 裡完全沒有這行**。
- **為什麼重要**：整個遊戲預期使用的「Noto Sans TC」與「Press Start 2P」字型都沒載入，手機改用系統內建字型顯示。iPhone 和 Android 字型不同，排版寬度會跟你在開發時看到的不一樣，按鈕文字可能換行或擠壓。
  - 實測：以手機尺寸開啟建置後的網站，瀏覽器已載入的網頁字型清單為「空」。
- **建議怎麼修**（擇一）：
  - 做法 A（推薦，最簡單）：把 Google 字型那行移到 `src/index.css` 第 1 行，`@import "tailwindcss"` 放第 2 行
  - 做法 B：刪掉 CSS 裡那行，改在 `index.html` 的 `<head>` 加 `<link rel="stylesheet" href="https://fonts.googleapis.com/...">`
- **怎麼驗證**：
  1. 執行 `npm run build`，終端機不再出現 `@import rules must precede` 警告
  2. 打開 `dist/assets/` 下的 `.css` 檔，搜尋得到 `fonts.googleapis.com`
  3. 手機開網站 → 字型看起來與開發時一致

### M3｜手機橫放時跑版，第 3、4 關按鈕或照片超出畫面

- **位置**：`src/components/StartScreen.jsx`、`src/components/Level3Photo.jsx`、`src/components/Level4Gacha.jsx`、`src/index.css`（`overflow: hidden`）
- **問題**：遊戲是以「手機直式」設計。實測直式 360×640、375×667、390×844 三種尺寸都正常；但**橫放（844×390）時**：

  | 畫面 | 現在會怎樣 |
  |---|---|
  | 開始畫面 | 「開始遊戲」按鈕變很寬，沒對齊背景的木牌 |
  | 第 3 關 | 照片卡高度約 476px，畫面只有 390px，照片下半部被切掉 |
  | 第 4 關結尾 | 「再玩一次」按鈕超出畫面底部，大部分看不到 |

  因為全站設定了「禁止捲動」，超出的部分無法捲動查看。
- **為什麼重要**：對方若沒鎖定螢幕旋轉、手機一歪就會看到破版，而且結尾無法重玩。
- **建議怎麼修**（擇一）：
  - 做法 A（推薦，改動最小）：偵測橫向時顯示一層提示「請將手機轉直再玩 📱」。在 `src/index.css` 用 `@media (orientation: landscape) and (max-height: 500px)` 顯示一個全螢幕提示即可，不用動各關卡
  - 做法 B：各關卡分別調整橫向版面（工作量較大）
- **怎麼驗證**：Chrome 開發者工具 → 裝置模式 → 選任一手機 → 按旋轉鈕，橫向時看到提示；轉回直向一切正常。

### M4｜開發用套件 13 個已知漏洞＋開發伺服器對區網開放

- **位置**：`package.json`、`package-lock.json`、`vite.config.js`（`server.host: true`）
- **問題**：
  - `npm audit` 結果：**13 個漏洞（7 高、5 中、1 低）**，全部在「開發工具」套件，包括 Vite 8.0.10（受影響範圍 8.0.0～8.1.5）、PostCSS、ESLint 等
  - `npm audit --omit=dev`（只看正式網站用到的套件）：**0 個漏洞**
  - `vite.config.js` 設定 `host: true`，讓同一 Wi-Fi 下的其他裝置都能連到你的開發伺服器（方便用 iPhone 測試）
- **為什麼重要**：
  - 好消息：正式網站是純靜態檔案，這些漏洞**不會**影響 GitHub Pages 上的網站
  - 風險在你自己的電腦：Vite 的漏洞多與「開發伺服器可能讀到專案外的檔案」有關。開發伺服器又對區網開放，在咖啡廳、公司等共用 Wi-Fi 執行 `npm run dev` 時，同網路的人理論上可以連進來
  - 比喻：家門鎖有已知瑕疵（Vite 漏洞），而且門是開著的（`host: true`），只是你只在自己在家時開門
- **建議怎麼修**：
  1. 執行 `npm audit fix`（所有修正都不需要大版本升級，相容性風險低）
  2. 把 `host: true` 移除，需要用手機測試時改用 `npm run dev -- --host` 臨時開啟
- **怎麼驗證**：
  1. `npm audit` 顯示 `found 0 vulnerabilities`
  2. `npm run build` 成功，`npm run dev` 能正常開啟遊戲並玩完 4 關
  3. 不加 `--host` 時，終端機只顯示 `Local:` 網址，沒有 `Network:` 網址

### M5｜遊戲背景、貼圖、參考截圖有版權疑慮

- **位置**：
  - 遊戲背景：`public/bg.jpeg`、`public/bg-select.jpeg`、`public/bg-select-clean.jpeg`
  - 角色動畫：`public/*.apng`
  - 只供參考、網站沒用到的資料夾：`楓之谷/`、`一番賞動畫參考/`、`角色/`（repo 根目錄）
- **問題**：背景來自商業線上遊戲畫面；角色動畫依文件記載來自 LINE 付費貼圖；`一番賞動畫參考/` 是其他網站的畫面截圖。這些素材在公開 repo 與公開網站上「再散布」。
- **為什麼重要**：LINE 貼圖的授權一般限於在 LINE 內個人使用；遊戲美術版權屬於遊戲公司。私人送禮的小網站被追究的機率低，但公開放在網路上就有被檢舉下架的可能。根目錄三個參考資料夾**對網站完全沒用**，公開只有風險。
- **建議怎麼修**：
  1. 立即：把 `楓之谷/`、`一番賞動畫參考/`、`角色/` 三個資料夾移出版控並加入 `.gitignore`（本機保留）
  2. 視需要：若擔心網站本身被檢舉，可考慮把 repo 改為私人，並改用其他不需要公開原始碼的方式託管（注意：GitHub 免費方案的私人 repo 無法使用 GitHub Pages，需評估付費方案或其他託管服務）
- **怎麼驗證**：`git ls-files | grep -E "^(楓之谷|一番賞動畫參考|角色)/"` 沒有輸出；網站仍可正常遊玩。

## 三、低風險

### L1｜gh-pages 分支殘留 `.claude/` 本機設定

- **位置**：`gh-pages` 分支根目錄的 `.claude/launch.json`、`.claude/settings.local.json`、`.gitignore`
- **問題**：這些檔案在 2026-05-07 的發布中被帶上 `gh-pages` 分支。`main` 已在 2026-10-29 移除 `.claude/`，但 `gh-pages` 工具預設「不碰點開頭的檔案」，所以之後每次發布都沒有把它刪掉。內容只是開發伺服器啟動設定，**沒有金鑰或密碼**。
- **為什麼重要**：任何人在 GitHub 切到 `gh-pages` 分支就看得到。目前網站應該不會直接提供這些檔案（GitHub Pages 預設會略過點開頭的檔案），但**如果日後加了 `.nojekyll` 檔，這些檔案就會變成網址可直接下載**。
- **建議怎麼修**：下次部署時，改用一次 `npx gh-pages -d dist --dotfiles`，讓工具把點開頭的舊檔一併清掉（`dist` 裡沒有點開頭的檔案，不會多傳東西）。清掉之前**不要**新增 `.nojekyll`。
- **怎麼驗證**：GitHub 網頁版切到 `gh-pages` 分支，根目錄看不到 `.claude` 資料夾與 `.gitignore`。
- **備註**：本次稽核環境無法連線到正式網站，以上依 `gh-pages` 分支內容判斷。

  - 舊版素材：`public/jump.mov`（1.6 MB）、`public/jump.mp4`、`public/jump_t.webm`（文件已註明棄用）、`public/char.png`、`public/char_t.png`、`public/bg-select.jpeg`、`public/icons.svg`
  - 重複檔：`public/一番賞圖片/瞬移石.jpg`、`public/一番賞圖片/神秘背包.jpg`（程式用的是 .png 版）
  - Vite 範本殘留：`src/App.css`、`src/assets/hero.png`、`src/assets/react.svg`、`src/assets/vite.svg`（未被引用，不會進網站，但讓專案看起來雜亂）
- **為什麼重要**：草稿頁可用網址直接打開；多餘檔案讓 repo 變肥、日後難判斷哪些在用。
- **建議怎麼修**：刪除上列檔案。
- **怎麼驗證**：`npm run build` 成功；`npm run dev` 玩完 4 關，所有圖片、動畫都正常顯示；瀏覽器開發者工具「Network」分頁沒有 404 錯誤。

### L3｜部分圖片仍有非定位的 EXIF 中繼資料

- **位置**：`public/bg.jpeg`、`public/一番賞圖片/神秘背包.jpg`、`public/一番賞圖片/瞬移石.png`、`楓之谷/` 內的圖、`角色/` 內的截圖
- **問題**：已逐檔檢查**目前版本所有圖片與影片都沒有 GPS 定位**（`public/photos/` 9 張照片已完全無 EXIF，與 `gh-pages` 上發布的版本相同）。但上列檔案仍帶有其他中繼資料（例如拍攝或編輯軟體資訊，本報告不列內容）。
- **為什麼重要**：通常無害，但可能透露裝置型號或編輯時間；一併清乾淨最省心。

### L4｜第 1、3 關計分程式寫法脆弱，lint 有警告

- **位置**：`src/components/Level1Quiz.jsx` 第 69 行、`src/components/Level3Photo.jsx` 第 164 行
- **問題**：作答函式用 `useCallback` 記住，相依清單只寫了 `[answered, qIdx]`，漏了 `score`。最後一題用 `score` 判斷是否全對。
  - 現在會怎樣：因為每題作答後 `answered`、`qIdx` 都會變，函式剛好會更新，**目前實測計分正確**
  - 為什麼仍要修：未來只要改動流程（例如加「跳過題目」），就可能出現「明明全對卻顯示沒全對」
- **建議怎麼修**：把 `score` 加進相依清單：`[answered, qIdx, score]`（兩個檔案各一處）。
- **怎麼驗證**：`npx eslint src` 不再出現 `missing dependency: 'score'` 警告；三題全對 → 顯示全對畫面；故意答錯一題 → 顯示未全對畫面。

### L5｜計時器沒有清除；註解與實際秒數不符

- **位置**：
  - `Level1Quiz.jsx`、`Level2Kuji.jsx`、`Level3Photo.jsx`、`Level4Gacha.jsx` 的 `setTimeout`
  - `Level1Quiz.jsx` 第 56 行註解寫「答對停留 3 秒」，實際程式是 1.5 秒（第 68 行 `1500`）
- **問題**：計時器在元件離開畫面時沒有取消。以目前流程，計時器跑完前無法切換關卡，**實際不會出錯**；但日後加入「跳關」「返回」按鈕時，可能出現已離開的關卡還在改狀態。
- **建議怎麼修**：目前可先不改；日後加導覽按鈕時，再用 `useEffect` 回傳清除函式。註解改為「答對停留 1.5 秒」。
- **怎麼驗證**：註解與數值一致；日後改動時，快速點擊跳關不會出現主控台錯誤。

### L6｜`npm run lint` 會失敗

- **位置**：`vite.config.js` 第 10 行、`eslint.config.js`
- **問題**：ESLint 設定把所有檔案都當成「瀏覽器程式」，但 `vite.config.js` 是在電腦上（Node.js）執行，用到 `process`，因此報 2 個錯誤，`npm run lint` 結束代碼為失敗。
- **為什麼重要**：檢查工具一直報錯，久了大家就不看，真正的問題會被忽略。
- **建議怎麼修**：在 `eslint.config.js` 為 `vite.config.js` 加一段設定，使用 Node 全域變數（`globals.node`）。
- **怎麼驗證**：`npm run lint` 只剩 L4 的警告（L4 修完後應為 0 個問題）。

### L7｜安裝了沒用到的套件 canvas-confetti

- **位置**：`package.json` 的 `dependencies`
- **問題**：彩帶效果是自己用程式畫的（`Level4Gacha.jsx` 的 `spawnConfetti`），沒有任何地方引用 `canvas-confetti`。
- **建議怎麼修**：`npm uninstall canvas-confetti`
- **怎麼驗證**：`grep -r canvas-confetti src` 沒有結果；`npm run build` 成功；第 4 關彩帶照常出現。

### L8｜金鑰掃描防護有缺口

- **位置**：`.githooks/pre-commit`、`.github/workflows/gitleaks.yml`、`README.md`
- **問題**：
  1. 本機掃描需要先執行 `git config core.hooksPath .githooks` 才會生效，README 沒寫，換電腦就失效
  2. 沒裝 gitleaks 時只印警告、照樣允許 commit（設計上的取捨，但容易忘記安裝）
  3. GitHub Action 用 `@v2`、`@v4` 這種可變動版本標籤，且沒有限制權限（`permissions:`）
- **為什麼重要**：防線看似有，實際可能沒開。目前已確認工作區沒有金鑰類檔案。
- **建議怎麼修**：
  1. README「開發」段落加上 `git config core.hooksPath .githooks` 與安裝 gitleaks 的說明
